## 二、⚠️ 一個必須先答嘅問題（唔答落唔到手）

**用戶撳「唔同意」之後會點？**

呢個唔係實作細節，佢直接決定咗成個閘嘅形狀，而且同憲章其他條文有衝突風險。

| 選項 | 行為 | 問題 |
|---|---|---|
| **A** | 唔同意 = 登入唔到，趕返去首頁 | ❌ 唔建議。同 §3「全部功能一律免費、無門檻」對撞。而且對一個焦慮學生嚟講，佢喺 sign-in 頁見到一道牆，好可能就此走咗 |
| **B**（建議） | 唔同意 = **照樣用得晒成個網站**，只係唔開雲端同步；本機 localStorage 一個字都冇少 | ✅ 同 §3 一致。同意閘守嘅係「你嘅資料離唔離開部機」，唔係「你用唔用得呢個網站」 |
| **C** | 唔同意 = 登出但保留本機 | 同 B 幾乎一樣，但會嚇親人（「我做咗嘅嘢係咪冇咗？」） |

**建議 B。** 理由：同意書真正授權嘅係**上雲**呢件事。網站本身唔使登入都用得（呢點 `/privacy` 已經明文寫住），所以將同意同「用唔用得」綁埋，係一個唔必要、而且傷害最需要幫助嗰批學生嘅設計。

⬜ **等你揀。**

## 三、Phase 2 會改嘅嘢（範圍）

### 3.1 新資料表 `privacy_consents`

沿用已剷走嗰張 `consent_logs` 嘅設計判斷（見 `0013_plus_payment.sql` 檔頭），
嗰啲判斷今日一樣成立：

```
user_id              text      邊個
policy_version       text      同意咗【邊一版】—— 冇呢欄，證據就淨係「佢撳過個掣」
consented_at         timestamptz
```

**刻意冇嘅嘢：** 冇 `ip_address`、冇 `user_agent`、冇家長電郵。
理由同 `0013` 完全一樣 —— 為咗同一個用途多開一個未成年人個人資料類別，唔值。

⚠️ 呢張表要行 §16.E 執行第 1 點：**新增上雲資料類別要創辦人書面批准。**
不過佢唔經 `lib/sync.ts` 白名單（唔係 localStorage 同步嘅嘢），係一張獨立表。

### 3.2 政策版本號 ＋ parity 閘

`/privacy` 頁文案一改，`POLICY_VERSION` 就要 bump，否則舊同意紀錄會扮成
「佢同意過新版」。**加一條測試：政策文案 hash 變咗但版本號冇 bump → fail build。**

呢個係全份規格入面最重要嘅一條 —— 冇佢，同意紀錄講唔出佢究竟同意咗乜。

### 3.3 現有 174 人補簽

下次登入彈一次，**唔可以擋住佢用網站**（見上面選項 B）。
文案要講清楚係「補簽」唔係「新條款」，唔好嚇親人。

### 3.4 文案要求（12–18 歲）

唔可以係一幅法律 wall of text。要答到三條問題，每條一句：
- 我哋攞你啲咩？（進度、逐課題答對率、未做完嗰節連你揀咗邊個選項、錯因自診）
- 攞嚟做咩？（**淨係做跨裝置同步，冇第二個用途**）
- 邊個睇到？（**淨係你自己**；§16.E 約束 2／3：禁第三方、禁跨用戶比較）

⚠️ 2026-09-08 之後上雲嘅嘢多咗兩樣（答案原文），所以呢份同意書
**比一個月前更加需要存在**。
