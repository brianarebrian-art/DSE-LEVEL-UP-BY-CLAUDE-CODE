# PRD：先備回溯與 FSRS

## 問題

學生在 M2 微分、化學電解或生物遺傳卡住時，如果直接看到最終式，下一次仍然不會做。固定的 3／7／14／30 日階梯也不會按這一次記得多少來改間隔。

## 用戶故事

作為一位香港 DSE 考生，我答不上微分的一步時，想先看到兩層先備，再回答一個不揭曉最終式的問題。連續三次仍未對上，我要換一題相似題和另一個例子的圖，而不是原題答案。

作為同一位考生，我做完這一步之後，想知道大約幾日後再練，而且這個數字只跟我自己的這張卡有關。

## 驗收

1. 答錯微分時，回溯結果包含代數，而且不包含進階作為先備。
2. 第一、二次提示分別是簡化與類比；第三次給出相似題與講解圖。
3. 提示文字不含該題正確選項的原文。
4. 新的 Good 評分，間隔約 3 日；可提取性在經過穩定度之後低於 0.9。
5. 未設定 `DATABASE_URL` 時，排程 API 仍可用，並註明沒有寫入資料庫。
6. 埠 5432 的連接字串被拒絕。
7. 頁面可由進度頁進入，中英文都可讀，沒有 emoji，沒有 FAIL。
8. 生產資料庫在創辦人批准前不套用 `0035` 草稿。

## 非功能

- 目標：1000 個同時在線時，這條純計算 API 的 P95 低於 300 ms。這是目標，不是已經在生產量到的數字。計算本身不打資料庫。
- 題庫讀取維持憲章的瀏覽器直連與靜態回落。
- 不新增付費 SDK，不呼叫語言模型。
- 學生列的 RLS 繼續用 `(SELECT auth.uid())`。這次 1000 行臨時表的兩種計劃都在 0.2 ms 以內；50 ms 的上限對這次樣本成立，不能外推成 100 萬行的證明。
