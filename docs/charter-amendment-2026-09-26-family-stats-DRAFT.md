## 一、要解決的問題

難度標籤目前沒有可靠依據：

| 事實 | 數字 | 來源 |
|---|---|---|
| 三個難度層的答對率統計上分不開 | χ² = 1.83，p ≈ 0.40 | `npm run qbank:accuracy-budget`（2026-09-10） |
| 選擇題逐題作答紀錄 | 26,261 題共 595 次 | `npm run qbank:calibrate`（2026-09-26） |
| 以課題實測校準可覆蓋的題目 | 38.8% | 同上 |

2026-09-26 已統一同一家族的標籤（`docs/difficulty-family-unification-2026-09-26.md`），但那只是令標籤一致，
並非按學生表現校準。要校準，就需要知道**每個題目家族**實際有多少人答對。

## 二、提案

| 項目 | 內容 |
|---|---|
| 新資料表 | `question_family_stats`：`family_key`（主鍵）、`subject`、`attempts`、`correct`、`updated_at` |
| **不收集** | 用戶 id、session id、帳號、電郵、IP、裝置、逐次作答時間、學生選了哪一個選項 |
| 單位 | 題目家族（`data/questions/family.ts` 的 `familyKey`），即同一科、同一課題、只差數字的一組題目 |
| 數據來源 | 現有 `/api/result/verify`。該路由已在伺服器重批每節答案；重批完成後，按家族把「作答次數」「答對次數」加到計數器 |
| 寫入方式 | 只經伺服器 `getServiceSupabase()`。anon key 對此表**無任何權限**（顯式 `revoke`，理由見 §3.1 約束 2） |
| 新增請求 | **零**。學生瀏覽器不發出任何新請求，沿用結果頁原有的一次覆核請求 |
| 用途 | 只用於重新推算家族難度標籤。**不顯示**給任何學生，不作任何跨用戶比較 |

### 標籤如何由數據產生（須一併批准）

- 家族累積 **≥ 30 次作答**才使用其數據；未達者維持現有標籤。
- 分界沿用 2026-09-10 的校準方法：答對率 ≥ 75% 為 easy，≥ 52.5% 為 medium，其餘為 hard
  （`scripts/qbank/calibrate-topic-difficulty.mts`）。
- 由 `scripts/qbank/gen-difficulty-overrides.mts` 按固定規則重算並提交，每次提交有 diff 及 `git blame` 可查。
- **須決定：** 由數據重算的標籤是否同樣「不需逐家族簽名」。本草案建議：規則本身經本修訂簽署後，
  按規則產生的改動不需逐家族簽名；但規則的任何改動須重新簽署。

## 三、對照現有憲章

1. **§16.E 約束 7（`question_events` 維持刪除）**：`question_events` 以 `user_id` 記錄每名學生答每一題的對錯。
   本表**沒有任何用戶欄位**，只有家族合計，無法還原任何一名學生答過甚麼。不構成復建。
2. **§16.E 約束 3（禁止跨用戶匯總比較）**：本表確屬跨用戶匯總，但匯總對象是**題目**而非學生，
   不產生排行榜、平均分、百分位或任何學生之間的比較。**須以本修訂明文加入例外**，並限定只用於難度校準。
3. **§16.E 約束 6（新增上雲資料須書面批准）**：本表不屬 `lib/sync.ts` 的用戶資料 key，但屬新增雲端資料，
   故以本文件開題。
4. **§3.1 約束 1、2（anon 只讀題庫）**：本表不開放給 anon key；寫入只經伺服器。
5. **§5 成本**：沒有新請求；每節一次小型 upsert（約 10 列）。資料表最多約 7,700 列。預計新增成本為零。
6. **`/api/result/verify` 的「零儲存」承諾**：該路由註釋寫明「唔寫 Supabase、唔寫 log、唔記 IP」。
   本提案把它改為「**只寫匿名家族合計**」。學生答錯了甚麼、選了哪個選項，仍然一律不儲存。
   私隱頁須同日加入一句說明（見下）。

## 四、風險

| 風險 | 說明 | 處理 |
|---|---|---|
| **數據被灌水** | 覆核路由不需登入、沒有限流（Vercel serverless 下記憶體限流無效，見路由註釋）。任何人都可以反覆提交假答案，把某家族推成 easy 或 hard | 每次請求最多計 `MAX_ANSWERS` 題；只計伺服器重批的結果；每個家族設每日增量上限；重算前檢查異常跳升。**無法完全防止**，只能令灌水成本升高、影響有上限 |
| **樣本有偏** | 用戶自選課題，而且整體答對率偏高（2026-09-09 基準：88.3%） | 分界以答對率計，偏差會令標籤整體偏易。結果頁已註明等級對應只是估算 |
| **數據累積慢** | 2026-09-09 基準共 5,565 題作答；7,687 個家族平均每個不足 1 次。要令大部分家族達 30 次，需要約 230,000 次作答，約為現有總量的 41 倍 | 大家族（模板題）累積較快，會先得到校準；其餘維持現有標籤 |
| **改標籤影響進行中覆檢** | 標籤改變抽題組合 | 每次由數據重算的提交須在 `docs/` 記錄日期，覆檢時按日期分段 |

## 五、不採用的做法

- **把逐家族對錯存入用戶的 `user_progress`，再跨用戶匯總**：會產生「用戶 × 家族 × 對錯」的資料，
  正是 §16.E 最警惕的組合，而且匯總時要讀全部用戶資料。匿名計數器從設計上就不帶用戶，較安全。
- **逐題統計**：題目太多、作答太少（帶題號的作答紀錄平均每題不足 0.03 次），統計上無意義。

## 六、簽署後要做的事（簽署前一行都不寫）

1. Migration：建立 `question_family_stats`，`revoke all` 予 anon 及 authenticated，只准 service role。
2. `/api/result/verify`：重批後按家族累加；更新路由註釋中的「零儲存」段落。
3. 私隱頁加入：「我們會匿名統計每類題目的作答及答對次數，用於調整難度標籤；不記錄是誰作答，亦不記錄你選了甚麼答案。」
4. `scripts/qbank/gen-difficulty-overrides.mts`：加入數據規則（≥ 30 次、75% ／ 52.5%）。
5. 測試：確保資料表及寫入路徑不含任何用戶欄位；anon 無權限。
6. 憲章 §16.E 約束 3 加入本例外；§16.E 執行第 1 點記錄本表。
