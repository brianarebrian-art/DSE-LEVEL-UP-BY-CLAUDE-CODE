## 二、決策理由

**場景（Yuna 原話）：** 「搭車落咗車、返到屋企想用個大啲嘅 mon（用 iPad）去做，
佢可唔可以繼續做返嗰個練習？……我唔想俾人一種失落感，即係手機做做吓，
返到屋企用 iPad 發現做唔到，會令到有焦慮嘅人好恐慌或者好焦慮。
我需要你明白，我哋係以人為本，唔係以成績為本。」

**取捨：** 答案原文留喺 server 嘅風險，對比一個焦慮症／SEN 學生換部機發現
進度全冇嘅打擊。按憲章 §1.1「學生成效與長期信任為最高原則」，選後者優先。

**點解唔揀選項 B（只上傳 `isCorrect`，剝走 `selectedZh`）：**
節末覆核 payload（`PracticeSession.tsx` → `/api/result/verify`）要 `selectedZh`。
剝咗，續做前嗰批題會被當成冇作答，學生會見到一個**靜靜計錯咗**嘅分數 ——
比私隱問題更差，因為佢冇聲。

## 七、⚠️ 一個順帶捉到嘅資料損失窿

`applyLocal` 用 `if (s.dse_topic_stats)` 判斷，而 **`{}` 喺 JS 係 truthy**。
一部未累積過嘅新機一旦上傳空值，就會將雲端已有嘅雷達／自診記錄**洗白，而且冇聲**。

已修：空物件／空陣列一律唔帶上去（`undefined` 對 `applyLocal` 嚟講＝「唔好郁」）。
迴歸鎖：`topic-stats-sync.test.mts`「三個 key 都係空嘅時候，一個都唔可以帶上去洗白雲端」。
