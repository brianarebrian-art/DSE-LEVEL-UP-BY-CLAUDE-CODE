# 題目家族難度統一（2026-09-26）

> **決定：** Yuna（COO）2026-09-26：「做第一步，唔需要簽名，立即生效。」
> **性質：** 只修正同一家族題目之間的標籤矛盾，**不是**按學生實際作答校準難度。
> **代碼：** `data/questions/family.ts`、`scripts/qbank/gen-difficulty-overrides.mts`、
> `data/questions/difficulty-overrides.generated.ts`；迴歸鎖 `data/questions/__tests__/family-difficulty.test.mts`。

## 問題

多個參數化題庫以迴圈序號派難度（`diff(i)`：`i % 10` 小於 3 為 easy、小於 8 為 medium、其餘為 hard），
目的只是湊夠 3:5:2。結果同一條題幹（只有數字或「第 N 組」不同）同時標作 easy、medium 和 hard，
標籤與題目內容無關。

2026-09-10 的實測亦顯示三個難度層的答對率在統計上分不開（χ² = 1.83，p ≈ 0.40）。

## 做法

1. **家族**：同一科、同一課題、題幹除數字外完全相同的選擇題。LaTeX 指令與文字不作簡化，
   故「求 2x³ 的導數」與「求 sin x 的導數」屬不同家族。
2. **規則**：每個家族取出現次數最多的標籤；打和時取較接近 medium 者；easy 與 hard 打和取 medium。
3. **套用**：題庫原始檔一字不改。覆寫表在組裝題庫時套用（`getSubjectQuestions`、瀏覽器後備路徑），
   伺服器、雲端同步、題庫版本號及練習抽題看到的是同一套標籤。
4. **不需逐家族簽名**：本次只改現有題目的難度欄，題目內容、答案、解說不變，亦沒有新題入庫。
   逐家族簽名按上述決定豁免，決定記錄於本文件。

## 仍然未解決

- **標籤只是一致，未必準確。** 家族內原本的標籤是隨機分配的，多數決只令同一家族說同一句話，
  並不代表該難度與學生實際表現相符。真正校準需要作答數據，見
  `docs/charter-amendment-2026-09-26-family-stats-DRAFT.md`（未簽署）。
- 結果頁「約 2–3 級／約 4 級／約 5 級或以上」的對應，繼續標明為平台估算。

## 對進行中實驗的影響（必讀）

每節按標籤 3:5:2 抽題，故改標籤會改變學生抽到的題目組合。以下兩個覆檢須**以生效日為分界**分開比較：

- §7.1 一節 10 題：2026-10-09 覆檢中途離開率。
- §7.2 反思鎖剷除：2026-11-09 覆檢逐週正確率。

**生效日 = 部署完成且雲端題庫同步完成之日。** 由執行部署的人填寫，不得預填（§16.C）：

| 項目 | 日期 | 執行人 |
|---|---|---|
| 部署到 production | ⬜ 待填 | ⬜ |
| `npx tsx scripts/qbank/sync-questions.mts --push` 完成 | ⬜ 待填 | ⬜ |

同步完成前，瀏覽器會發現雲端題庫版本與網站不符，改用網站內置題庫，而內置題庫已套用新標籤。

## 維護

新增或修改題目後依次執行：

```
npm run qbank:family-difficulty
npm run gen:summary
```

覆寫表過時或有家族仍然矛盾時，`npm test` 會失敗。
