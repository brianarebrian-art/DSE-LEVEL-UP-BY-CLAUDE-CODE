## 一、🛑 我唔會建嘅三項

### 1.1 將未成年人嘅精神科標籤存入雲端資料庫

提案（第四戰區，Alan）：

```sql
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS sen_tags TEXT[] DEFAULT '{}';
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS sen_preferences JSONB DEFAULT '{}';
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS mood_log JSONB DEFAULT '[]';
ALTER TABLE profiles ADD COLUMN IF NOT EXISTS sleep_log JSONB DEFAULT '[]';
```

配合 Max（CTO）嘅一句：「**全部數據上雲**（C-Strict標準），localStorage 只存匿名 session」。

**呢個會將一個 12–18 歲學生嘅精神科診斷（抑鬱、躁鬱、PTSD、飲食失調、自閉症、
ADHD…）連同 `user_id` 存喺一張雲端表。**

| 撞乜 | 原文 |
|---|---|
| 安全重規劃 §二 | 「建立、匯出、人工閱讀或持續追蹤某學生的…**情緒日誌**」= 絕對禁止 |
| 安全重規劃 §三 | 「不收真名、學校、聯絡方式、成績、答案原文、錯題、**情緒資料**」 |
| 安全協議 §二 | 新資料欄位 → **不可先做再問** |
| 憲章 | 資料 100% localStorage；Supabase 只作 server-side 備份 |

而且方向同我哋**前日**（`9adc536`）先做嘅嘢**完全相反** —— 嗰陣我哋因為
「答案原文」太敏感而將佢由雲端剝走。精神科診斷比答案原文敏感一個數量級。

`mood_log` / `sleep_log` 更加係逐日心理狀態時序 —— 正正就係文件禁嘅「情緒日誌」。

**風險唔止合規：** 一個 15 歲學生嘅抑鬱症標籤一旦入咗雲，資料外洩、家長查閱、
將來升學／保險場景全部係實質傷害。呢個唔係我可以代學生承擔嘅決定。

### 1.2 自動情緒偵測 + 自動危機介入

提案三處：

| 位置 | 原文 |
|---|---|
| T1「心境惡劣障礙」 | 「若用戶**連續 7 日**選擇『今日心情：差』，**主動推送**『你可能需要傾下計』資源」 |
| T1「自我傷害」 | 「若用戶**搜索相關內容**，**觸發**『你唔係一個人』緊急資源頁面」 |
| Phase 2 | 「上線『**自殺危機干預流程**』」 |

**呢個係平台對未成年人做心理狀態判定，然後自動介入。**

點解唔可以：

1. **假陰性會殺人。** 一個真正有危險嘅學生唔一定連續 7 日撳「差」，
   亦唔一定會喺我哋度搜嘢。我哋建咗個「安全網」，但佢接唔住人 ——
   而平台已經對外聲稱有網。
2. **假陽性會傷人。** 連續 7 日心情差可能係失戀、屋企事、或者單純攰。
   彈一個自殺資源出嚟，係將一個唔開心嘅學生標籤成有自殺風險。
3. **接唔到真人。** 「危機干預流程」介入之後由邊個跟？我哋冇 24 小時真人。
   提案第二戰區列咗「Sarah（社工）」講嘢 —— **Sarah 係虛擬 persona，唔係真人社工。**
   將學生轉介去一個唔存在嘅人，係最危險嗰種假承諾。

**負責任嘅版本已經上線：** `/waiting` 有靜態危機熱線信號牌，
真實已驗證號碼（撒瑪利亞會 **2896 0000**）+ 醫療免責。
唔偵測、唔判定、唔介入 —— 只係永遠喺度，學生自己撳。

⚠️ 呢一項我記錄過：之前有一版憲章（54-Idea v2 SEN-07）提出過完全相同嘅嘢，
當時已經判定唔建。**呢次係第二次。**
