**對唔上。** 而且 `0.5000` 啱啱好等於二分搜尋嘅下界：

```ts

```

即係話嗰個「擬合結果」比較似**搜尋冧咗落地板**，唔係收斂。

### 而個二分搜尋本身有 bug

```ts
const avgError = (err5 + err4 + err3) / 3;      // 三個等級一齊算誤差
if (errorMetrics.simulatedOver5 > targetDistribution['5']) { … }  // 但只睇 5 級去調 k
```

收斂條件用三級平均誤差，方向卻只由 5 級決定。三者唔一致嗰陣（正常情況）
永遠收斂唔到，行夠 15 次就交返當時個中點 —— 個「最優 k」係一個任意值。

同一個 bug 喺 `.py` 版第 344–398 行照樣存在。

## 五、防線 4「作弊偵測」撞大愛設計（憲章 §7）

算法會向學生輸出：

> 「偵測到大量快速作答（X% 的題目答題時間小於 4 秒）。為建立健康溫習習慣，
> 此評估已**熔斷失效**。請保持專注重新練習。」

> 「作答型態**異常**（例如連續選用相同選項比例過高…）。為維護算法可信度，
> 已**暫停**本次等級估算。」

呢個係向學生指控作弊。實際會誤判：

- **ADHD 學生**答得快 → 被當成浮躁
- **熟到爆嘅學生**秒答基礎題 → 被熔斷
- 連續揀同一個字母 ≥75%：四選一之下，12 題連續 9 題同一個答案**係會自然發生**
  （而且選項每次 render 都洗牌，所以「連點同一位置」根本唔等於同一個答案）
- 「難易倒掛」（L1 <10% 但 L3 >85%）會將**知識分佈唔平均**嘅學生當成可疑 ——
  例如一個死記硬背唔識但推理好嘅學生

§7 明文禁止打擊自信嘅元素。「你疑似作弊」係最重嗰種。
