**文件版本：** 1.0.0
**日期：** 2026-10-31（Asia/Hong_Kong）
**負責人：** 首席全端工程師兼保安負責人
**狀態：** Phase 2 完成，等待批准進入 Phase 3

## 1. 核心問題陳述 (Core Problem Statement)

> **「學生唔係缺乏題目，而係缺乏一個能幫佢哋知道『錯喺邊、點樣修復、幾時重溫、有冇進步』嘅免費學習系統；同時平台需要足夠安全同透明，先值得學生交付學習數據。」**

目前 DSE Level Up 累積了超過 27,000 條原創平行改寫題目，涵蓋 25 個科目，並具備基礎題目練習與即時解析能力。但回訪數據與學生體驗顯示：
1. **「做完就算」的練習盲區：** 學生答錯題目後，散落於本地瀏覽器記錄，缺少強制修復引導與認知診斷；下一次遇到同類題型或同邏輯變式題依然重覆犯錯。
2. **缺乏結構化進步反饋：** 學生面對海量課題，不知道「自己目前到底弱喺邊度」、「今日最值得做嘅一件事係咩」；現有估算等級區間與複雜圖表反而增加資訊焦慮。
3. **數據交付的信任門檻：** 若要跨裝置記錄錯題與學習路徑，學生必須登入並將學習軌跡託管於伺服器；若平台保安防線（RLS、IDOR 防護、外洩應變）不夠嚴密透明，學生與家長將對交付學習資料產生顧慮。

## 2. 目標用戶畫像與需求 (Target Users)

1. **主流 DSE 中四至中六考生：**
   - **特徵：** 時間緊迫，面對多科溫習壓力；常於學校小息、搭車或自修室進行 15-30 分鐘短節溫習。
   - **痛點：** 盲目「操 Past Paper」卻反覆在相同邏輯陷阱失分；無法量度自己溫習的成效。
   - **需求：** 每次練習只需清楚知道「錯喺邊一步、點解錯、下次點避免」，並能在 3/7/14 日後收到溫和重溫提醒。
2. **需要無障礙 (SEN) 與情緒安全空間的考生：**
   - **特徵：** 包含讀寫障礙、注意力不足 (ADHD) 或考試焦慮傾向學生。
   - **痛點：** 倒數計時器引起心慌、字體過小易跳行、被過度遊戲化（連續斷卡懲罰、排行榜比較）打擊自信。
   - **需求：** 閱讀尺、高對比度易讀字體、完全可關閉壓力倒數、零排名的安靜專注介面。
3. **關心內容可信度與私隱的老師與家長：**
   - **特徵：** 期望學生使用正向、合法的輔助學習工具。
   - **痛點：** 市面補習平台充斥未經審核的內容或隱蔽付費陷阱；擔心學生個資被轉售或洩漏。
   - **需求：** 明確題目來源（原創改寫 vs 公開資料衍生）、透明審核狀態、嚴謹透明的私隱保護與隨時徹底刪除帳號權限。

## 3. 核心用戶旅程 (Core User Journey)

### 3.1 首次使用體驗：10 分鐘入門診斷
1. **進站引導：** 學生進入首頁，清楚看見「免費、透明、唔催逼」承諾，選擇弱項科目。
2. **診斷前測：** 進行 10 題核心診斷練習（約 10-12 分鐘），涵蓋該科核心概念與高頻陷阱。
3. **即時診斷結果：** 答完後立即產出「薄弱課題分析」，清晰標示 Top 3 優先補救課題，並自動生成每週建議路線（例如每週 3 次、每次 15 分鐘）。
4. **自主選擇同步：** 提示「可使用 Google 跨裝置同步錯題本；未登入亦能完整本機練習」，不強制阻擋。

### 3.2 日常溫習循環：定向修復與間隔重溫
1. **今日唯一行動 (Next Best Action)：** 登入或打開 Dashboard，頂部只顯示一項最優先行動（例如：「今日重溫 3 條幾何錯題」或「完成課題節測」）。
2. **深度解析與錯因自診：** 答錯時，啟發式分步揭曉提示；完成後標註錯因標籤（概念 / 題意理解 / 計算符號 / 單位格式 / 陷阱邏輯）。
3. **間隔重溫閉環：** 系統於第 3、7、14 日將錯題或同邏輯變式題排入重溫列表。重做通過後，該課題的弱項風險評級下降；若未通過，自動推薦前置概念題目。
4. **1 分鐘結算覆盤：** 練習結束時，給予客觀掌握度增量反饋，絕無排名或比較文案。

## 4. 成功指標 (Success Metrics)

為客觀證明「有冇進步」與「平台保安可信」，本次更新設立以下可量度指標：

| 指標類別 | 指標名稱 | 目標基準 (Target) | 量度方式與來源 |
| :--- | :--- | :--- | :--- |
| **產品學習指標** | **錯題重做率 (Mistake Retry Rate)** | $\ge 40\%$ | 本節/排程產生之錯題，被學生主動點擊重做的比例 |
| | **錯題重做通過率 (Retry Pass Rate)** | $\ge 70\%$ | 重做錯題時成功答對的比例（證明認知修復） |
| | **7 日 / 14 日 Retention Check 完成率** | $\ge 35\%$ | 間隔到達時完成指定重溫題集的學生比例 |
| | **每週學習路線完成率** | $\ge 50\%$ | 接受診斷後，每週完成 3 次短節練習之比例 |
| | **儀表板 Next-action 點擊率** | $\ge 60\%$ | 進入 Dashboard 後點擊主要行動按鈕的轉化率 |
| **內容與信任指標** | **內容錯誤回報處理時間** | $\le 48 \text{ 小時}$ | 學生提交題目回報至團隊審核並更新狀態的時間 |
| | **審核狀態覆蓋透明度** | $100\%$ | 全庫題目具備清晰 Provenance 與當前審核狀態標籤 |
| **保安與系統指標** | **P0 Security Finding 修復時間** | $\le 24 \text{ 小時}$ | 任何高危漏洞由發現至發布 hotfix 並完成驗證的時間 |
| | **Critical Dependency CVE 修復時間** | $\le 72 \text{ 小時}$ | 依賴庫重大漏洞升級並通過迴歸測試的時間 |
| | **核心 API Error Rate** | $< 0.1\%$ | `/api/progress`, `/api/sync/*`, `/auth/callback` 5xx 比例 |
| | **核心練習流程 p95 Latency** | $< 250 \text{ ms}$ | 練習換題、提交答案、解析揭曉的伺服器響應時間 |

## 5. 明確非目標 (Explicit Non-Goals)

為保持產品專注、防範範疇蔓延 (Scope Creep) 並嚴守憲章倫理，本次大更新明定以下非目標：

1. **擱置教育型 AI 助手：** 嚴禁引入 AI Chatbot、LLM runtime 生成答案、AI 即時對話。所有解析必須是嚴謹的人工編寫或經審定版本，防止 AI 幻覺誤導考生。
2. **暫緩全科長卷模擬試卷：** 不做長達數小時的全科長卷模擬考試，堅持聚焦於 10-15 分鐘的高效微型練習與課題節測。
3. **暫緩 DSE 等級預測：** 不向學生提供「保證 Level 5**」或虛假等級預測，避免將相關性包裝為因果承諾。
4. **暫緩社交與社群功能：** 不設討論區、留言板、好友動態或任何社交互動，杜絕霸凌與分心風險。
5. **暫緩深度家長監控：** 不提供家長即時行蹤監控或強制匯報機制，尊重考生的自主學習空間與心理安全感。
6. **暫緩複雜遊戲化：** 不引進經驗值、金幣、排行榜、懲罰性連續天數 (Streak)；以內在學習進步感替代外在刺激。

## 6. 約束條件與邊界 (Constraints)

1. **零停機與零破壞 (Zero Downtime & Zero Regression)：** 更新期間不可導致線上中斷，不可刪除、覆寫或損壞任何現存學生之進度與設定資料。
2. **成本死鎖與技術棧限制：** 遵守月預算 $\le \text{US}\$200$，不引入需付費之第三方 APM、雲端追蹤工具（如 PostHog、Datadog）或圖表套件。
3. **嚴格伺服器端授權：** 所有 Server Actions 與 Route Handlers 必須於伺服器端重新驗證身分（`getSyncUserId()` / `auth.uid()`），拒絕前端傳入之未經校驗 ID。
4. **最小權限 RLS：** 所有敏感表（學習進度、設定、稽核日誌）一律 Deny All，僅由驗證通過之身分或授權服務讀寫。
5. **完全無障礙相容：** 符合 WCAG 2.1 AA 標準，所有練習控制項必須遵守 48px 觸控目標高（`min-h-12`），學生端文字與 UI 嚴禁 Emoji。

## 7. 產品與技術風險 (Risks & Mitigations)

| 風險項目 | 風險描述 | 緩解措施 (Mitigation) |
| :--- | :--- | :--- |
| **錯題膨脹風險** | 學生長期答錯累積大量錯題，造成重溫隊列過載而產生挫敗感。 | 每日重溫上限封頂為 5 題（`DAILY_REVIEW_LIMIT`），依艾賓浩斯曲線動態平滑分配。 |
| **跨裝置同步競爭** | 用戶在手機與電腦同時做題，導致本地快照與雲端進度產生覆蓋衝突。 | 採用以伺服器時間戳為基準的欄位級合併（Field-level Merge），並在登出/抹除時設鎖。 |
| **資料庫查詢負荷** | 新增錯題與重溫排程查詢若未建立適當索引，將拖慢資料庫效能。 | 在相關關聯鍵（`user_id`, `topic_id`, `due_date`）建立組合索引，並避免大表 JSON 全表掃描。 |
| **題庫版本不一致** | 本地 IndexedDB 快取與雲端最新修正版本脫節，導致學生看到已下架或有錯誤之題目。 | 利用 `question_bank_versions` 的 SHA-256 輕量雜湊機制，於每次練習初始化時進行比對。 |

## 8. 核心假設 (Assumptions)

- **假設 1 (學習成效)：** 學生需要「針對錯題的針對性復習與錯因診斷」，多於單純海量刷全新題目。
- **假設 2 (認知引導)：** 5 大錯因標籤（概念/題意/計算符號/單位格式/陷阱）能有效促使學生反思錯誤本質，從而提高重做通過率。
- **假設 3 (學習節奏)：** 每週 3 至 5 次、每次 15 分鐘的微型學習路線，其依從度與長期完課率顯著高於無指引的自主選科刷題。
- **假設 4 (決策效率)：** 進度儀表板提供唯一的「Next Best Action」，能顯著減少考生登入後的猶豫時間，提高回訪行動率。
- **假設 5 (品牌信任)：** 題目來源類別、改寫邏輯與審核狀態全透明公開，能提升考生與家長將學習數據託管於平台的信任度。
- **假設 6 (留存閉環)：** 永久免費且無催逼的間隔重溫閉環，能夠在不依賴遊戲化懲罰的前提下自然帶來穩健留存。

## 9. MVP 邊界定義 (MVP Boundary for v1)

在即將開展的大更新中，MVP 邊界嚴格劃定如下：

### 必須納入 MVP (Must-Haves)
1. **錯題復習系統：**
   - 錯題本檢索與一鍵重做。
   - 5 大客觀錯因標籤紀錄與過濾。
   - 3/7/14 日間隔重溫排程與通過後弱項風險降級。
2. **輕量學習路線：**
   - 10 分鐘入門診斷與 Top 3 弱項識別。
   - 每週建議學習路線排程（每週 3-5 次）。
   - 每次練習結束的 1 分鐘覆盤。
3. **透明進度儀表板：**
   - 0-100 科目 Mastery Score。
   - 「今日唯一行動」指引。
   - 題目來源、改寫重點與審核狀態標籤。
4. **保安與合規底線：**
   - 伺服器端統一身分與授權校驗，杜絕 IDOR。
   - 敏感資料表全面 RLS 鎖定。
   - 關鍵端點安全性輸入校驗與錯誤訊息脫敏。

### 延後至後續版本 (Nice-to-Haves / Post-MVP)
- 跨科目整合失分地圖深度交叉分析。
- 學生自主客製化個人學習步調進階調整器。
- 更多複雜非選擇題型的結構化多步提示擴充。

## 10. Phase 3 驗證計劃概覽 (Phase 3 Validation Plan Preview)

在進入 Phase 4 正式系統設計前，Phase 3 將針對前述關鍵假設，設計「低成本、高信度、零破壞」之驗證方案：
- **驗證方式：** 採用 Staging 原型模擬、小樣本訪談 (Small Cohort)、及非侵入式匿名統計指標。
- **驗證重點：** 錯題重做意願、錯因標籤清晰度、每週學習路線完成阻力。
- **退出準則：** 若核心假設驗證失敗，及時調整設計或縮小功能範疇，絕不盲目推進高成本開發。
