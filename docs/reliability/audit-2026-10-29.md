## 1. 可靠性目標與關鍵失敗模式

### 1.1 最不可失敗嘅 10 個時刻

| # | 時刻 | 失敗後果 |
|---|---|---|
| 1 | 首屏可開、未登入可進練習 | 產品承諾「未登入亦可」崩 |
| 2 | 題庫載入成功並抽到可做嘅 MC | 空卷／假題庫 → 失去信任 |
| 3 | 選項顯示正確、可點選 | 卡住＝核心流程中斷 |
| 4 | 提交後即時對錯判斷正確 | **批改錯＝最嚴重信任摧毀** |
| 5 | 解釋可見且對應本題 | 學錯／誤解 |
| 6 | 本節分數／表現帶計算正確 | 動機與決策失真 |
| 7 | `recordAttempt` 寫入本機成功 | 進度消失 |
| 8 | 書寫題只自評、永不機器批改 | 違反產品原則 |
| 9 | 已登入時同步唔 orphan／唔洗白 | 跨裝置進度災變 |
| 10 | 匯出／匯入唔損毀、唔靜默覆蓋雲端 | 資料主權承諾崩 |

### 1.2 直接破壞學習信任嘅錯誤

- MC 以錯誤答案 key 判對／判錯
- 進度寫入後消失或被同步洗走
- 同一節重複抽同一題（「假題庫」感）
- 表現估算明顯誇大（歷史：`score=10000/total=100` 污染全域準確率）
- 匯入後頁面 crash 或覆蓋本機且無法還原
- 書寫題被機器打分並入總準確率

### 1.3 用戶未必即時發現、但長期損害

- 統計偏差（自評混入客觀指標、小樣本當等級）
- Schema／migration DRAFT 與 prod 脫節
- 雲端題庫版本漂移 → 靜默回落靜態 chunk
- localStorage 損壞被 soft-drop，分析腳本各自過濾不一致
- 無障礙／效能退化
- 依賴漏洞、rate-limit 多 isolate 可繞過
- Soft-fail 令「失敗冇聲」累積（sync null、attempt 被擋）

### 1.4 最脆弱三條關鍵路徑

1. **MC 批改錨**：`correctIndex` → `correctZh` → `zh === correctZh`（`PracticeSession.tsx`）
2. **進度本機 → sync merge → `user_progress`**（`progress.ts` → `sync.ts` → `/api/progress`）
3. **匯出／匯入白名單覆寫**（`DataPortability.tsx`）↔ 登入後 `pullMerge`

### 1.5 只能保證永遠正確嘅三件事

1. **MC 批改正確**（文字錨，唔靠洗牌後 index）
2. **書寫題永不機器批改、永不入 `recordAttempt`**
3. **進度寫入衛生 + sync 合併唔整份二選一丟節**

### 1.6 可靠性目標卡（可量度）

| 目標 | 指標 | 目前風險 | 偵測 | 責任範圍 |
|---|---|---|---|---|
| 核心練習可用性 | 練習 session 錯誤率；空卷率；BankLoadError 曝光 | 雲 soft-fail 回落；elective 空→整庫；無 health | Sentry + 合成探針 + `/api/health` | PracticeGate / load / questionCloud |

## 2. 核心用戶旅程與風險地圖

```
開始練習 (PracticeGate)
  ├─ loadSubjectMCQuestions / loadWrittenQuestions
  │    ├─ loadFromCloud → 有長度則用；否則靜態 chunk
  │    └─ fail → BankLoadError；未知科 → []
  ├─ inScope(electives)：kept.length ? kept : bank  ← 空篩選回整庫
  └─ PracticeSession | LongPracticeSession

作答 → 提交
  MC: prepareQuestion → correctZh = options[correctIndex]
      isCorrect = zh === correctZh
  書寫: SelfAssessment → recordTopicOutcomes；永不 recordAttempt

即時批改／解釋 → 更新進度
  recordAttempt → isPossibleAttempt soft-fail
  notifyProgressChanged → debounced push（已登入）

表現估算
  practiceBand（本節語言）／predictGrade（部分路徑仍寫入 attempt.grade）

同步／匯出
  SyncProvider pullMerge → mergeSnapshots（progress union + topic 三方合併）
  DataPortability：白名單 setItem 覆蓋 → reload → 再 merge
```

| 步驟 | 資料來源 | 狀態轉換 | 失敗點 | 現有防護 |
|---|---|---|---|---|
| 載題 | cloud / chunk | null→bank | 雲故障、空陣列 | 回落 chunk；BankLoadError；totalQ=0 UI |
| 抽題 | bank + seen | pool→session | 假重複 | orderUnseenFirst |
| 批改 | correctZh | answerState | 重複選項文字 | 現庫 0；無 runtime 閘 |
| 寫進度 | localStorage | attempts+1 | quota／髒分數 | isPossibleAttempt；isUsableAttempt 讀取 |
| Sync | /api/progress | merge | getSyncUserId null→401 | 拒猜 key；union merge |
| 匯入 | JSON file | 覆蓋 keys | 鬆驗證、唔 merge | format／白名單／二次確認／2MB |

## 4. 三個未被提出嘅深度盲點

### 盲點 A — 匯入白名單寬、雲同步白名單窄，且匯入唔經衛生閘

- **證據**：`DataPortability` PORTABLE_KEYS 含 `dse_result`／`dse_daily_spectrum`／`dse_review_done`；`sync.ts` KEYS 唔含呢啲。`dse_progress` 匯入只 `Array.isArray`；`snapshotLocal` 用 `readJSON` **唔**跑 `isUsableAttempt`。
- **影響**：髒 attempt 可進本機再上雲；結果頁靠 `readStoredResult` 硬撐（已有測證明 `{}` 過匯入閘）。
- **驗證**：構造 `dse_progress:[{score:9,total:1,...}]` 匯入 → 查 localStorage／sync payload。
- **行動**：匯入深驗證 + 寫入前 filter；snapshot 上雲前衛生。

### 盲點 B — 「失敗冇聲」疊加（sync null × attempt soft-drop × cloud soft-fail）

- **證據**：`getSyncUserId`→null；`recordAttempt` soft return；`loadFromCloud`→null 回落 chunk（設計正確但對用戶不可見）。
- **影響**：學生以為「登入＝雲備份」「做完＝已記」「最新題庫」——三者都可能靜默唔成立。
- **驗證**：斷網／拔 key／mock listUserAccounts throw；看 SyncStatus 文案。
- **行動**：分級可見狀態（唔打擊自信、但要誠實）。

### 盲點 C — elective 空篩選回整庫，同「假題庫」歷史同類

- **證據**：`PracticeGate.inScope` L203；檔頭註解承認防空卷。`LongPracticeSession` 曾用純 random 導致覆蓋極差（檔頭 L86–92 實測）。
- **影響**：選修設定失效時學生練到範圍外題，以為產品無視設定。
- **驗證**：選空 electives／損壞 `dse_electives`。
- **行動**：UI 明示回落；考慮拒絕開卷並引導重選。
