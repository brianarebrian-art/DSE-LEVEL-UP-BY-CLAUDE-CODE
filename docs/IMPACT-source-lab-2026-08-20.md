# Phase 1 影響評估：歷史百科 → 史料判讀室

**狀態**：read-only 評估，**未動任何代碼**。依 CLAUDE.md §4（>3 檔變更須先出 impact report，待 Brian／Yuna greenlight）。
**決策來源**：Yuna 2026-08-20 —— 「歷史百科係 DSE Level Up 新嘅功能」。

## 1. 這個功能實際上是什麼

原文件叫「全球客觀歷史百科」，定位是給全球讀者的獨立知識平台。作為 DSE Level Up 的功能，它應該改名換位 —— 但**三層結構本身值得原封不動保留**，因為它剛好命中 DSE 歷史科的核心考核技能。

DSE 歷史科**卷一是資料題**。考的正是：

| 卷一要求 | 三層結構對應 |
|---|---|
| 分辨史實與史家詮釋 | 事實層 vs 解釋層 |
| 識別史料立場與偏見 | 立場層 |
| 評估史料可靠性 | Primary / Secondary / Tertiary 標註 |
| 比較不同視角 | 等寬並列卡片，無主次 |

而 `data/questions/history.ts:22` 已經聲明咗一個框架：

```ts
evidence: { id: 'evidence', zh: '史料判讀', en: 'Source Analysis', emoji: '🔍' }
```

即係：題庫已經宣稱要考史料判讀，但 MC 題型只能考到皮毛 —— 學生揀完 A/B/C/D，冇練到「面對一份有立場的史料，點拆」。**這個功能補的正是那條軸。** 它不是新增一個無關的百科，是把一個已存在但只能半做的能力做完。

**建議命名**：史料判讀室（Source Lab）。「百科」oversell 咗，而且我哋唔係做百科。最終命名係 Yuna 決定。

## 2. 範圍（最重要的一項）

### 2.1 建議做：課程內

`data/questions/history.ts` 現有 8 個課題，全部有多方史料可用：

| 課題 id | 中文 | 多視角材料是否天然存在 |
|---|---|---|
| `ww1` | 第一次世界大戰 | ✅ 戰爭責任條款（凡爾賽和約 231 條）各方詮釋 |
| `ww2` | 第二次世界大戰 | ✅ 綏靖政策評價分歧 |
| `cold_war` | 冷戰 | ✅✅ 柏林封鎖、古巴導彈危機、韓戰 —— 美蘇雙方敘事完全對立 |
| `dictatorship` | 極權主義興起 | ✅ 威瑪崩潰成因之爭 |
| `intl_coop` | 國際合作 | ✅ 國聯失敗歸因 |
| `china_mod` | 中國現代化 | ✅ |
| `japan_mod` | 日本現代化 | ✅ |
| `hk_seasia` | 香港與東南亞 | ✅ |

冷戰一項就已經足夠讓「多視角並列」機制吃飽 —— 而且係考評局年年出、學生最易失分嗰部分。

中史（`chinese-history`）同理，歷代制度變革的史家評價分歧本身就是考點。

### 2.2 建議唔做：原文件的時間線骨架

原文件要求建立史前 → 古代 → 中世紀 → 近代 → 現代 → 當代六個時代，共約 40 個條目，示範內容指定**宇宙大爆炸**同**1967 年六日戰爭**。

三個理由：

1. **通唔過憲章 §2 受眾關** —— 美索不達米亞、印度吠陀時代對 DSE 考生零分數價值。原文件自己嘅 harness §四受眾關寫住「涉及全齡層立即攔截」，佢自己違反咗自己。
2. **學生時間** —— 一個中六生剩返 30 日，唔應該喺我哋個平台度睇黑死病。
3. **編輯負擔 vs 回報** —— 以巴衝突、烏克蘭戰爭係進行中衝突，要持續更新、承受最高審視強度，而換返嚟嘅 DSE 分數係零。呢個係典型嘅高風險零回報。

**六日戰爭尤其唔建議做**：唔喺 DSE 課程，而且係現存最具爭議嘅歷史題目之一。要示範「三層分離處理爭議」，冷戰嘅**柏林封鎖**或**古巴導彈危機**係更好嘅示範 —— 同樣係美蘇敘事完全對立、同樣需要三層分離，但佢喺課程入面，學生睇完可以直接攞分。

如果你係想要一個獨立嘅全球歷史百科網站（唔係 DSE 功能），嗰個係另一件事，另外開工。

## 3. 🔴 最硬的一條：來源不可以砌

原文件要求每條 `[FACT]` 標註「具體文件／機構／**檔案編號**／URL」。

**我唔會發明檔案編號。** 呢條喺歷史科比其他科更致命：

- 一個學生喺 DSE 卷一資料題引用一個唔存在嘅檔案編號 → 直接扣分，而且係我哋教壞佢
- 歷史科老師一查即穿，整個平台信任度歸零
- 呢個係憲章「不虛構數據」嘅最尖銳版本

執行規則：

| 情況 | 做法 |
|---|---|
| 可查證嘅公開文件（凡爾賽和約條款號、聯合國決議編號、已公開檔案）| ✅ 引用，附可核連結 |
| 學術著作、史家觀點 | ✅ 引用作者 + 著作 + 出版年，標 Secondary |
| 查唔到具體編號 | ⚠️ 標 `[來源待查]`，**留空唔填**，唔上線 |
| 任何情況 | ❌ 唔准為咗填滿格式而生成一個似模似樣嘅編號 |

**真人審批環節必須加一項：逐條核來源。** 呢個係入庫流程之外嘅額外一關，因為題庫嘅 gate 檢查格式，檢查唔到「呢個檔案編號係咪真嘅」。

## 4. 技術影響

### 4.1 格式：建議用 typed TS，唔用 .txt

原文件要求純 `.txt` + `==標記==` 分層，理由係「非技術人員用 Notepad 即可編輯」。

現有先例係 `data/reading.ts` —— typed TS 內容檔，配一個 `/reading` 路由。建議跟返：

| | typed TS | 純 .txt |
|---|---|---|
| term-guard / i18n-guard 掃到 | ✅ 已經掃 `.ts` | ❌ 要改 guard |
| 型別安全（漏咗來源欄即編譯失敗）| ✅ | ❌ |
| 新增 parser | 唔使 | 要寫 + 要測 |
| 非技術人員 Notepad 編輯 | ❌ | ✅ |

最後一行係唯一嘅取捨。**如果你預期將來會有非技術人員（例如榮譽協作者）直接編輯內容，.txt 係啱嘅選擇**，我照做，只係要多寫一個 parser 同佢嘅測試。你決定。

### 4.2 主題

原文件指定暗色 `#0F0F0F` + 霓虹四色。Live 係 light-first。**用返現有 token**（`--color-surface` / `--color-ink` / `--color-accent`），唔另開色系 —— 否則就係 audit 報告 §1.3 講嗰個「第二套平行 token 系統」問題。

原文件嘅視角卡片邊框色（藍 `#3B82F6` / 綠 `#10B981` / 紫 `#8B5CF6` / 灰 `#6B7280`）要重新對比度驗證先用，唔可以照抄。

### 4.3 成本

純靜態 SSG，零資料庫、零 API、零新 dependency → **$0**，過預算關（US$200 上限，見 CLAUDE.md §1.5）。

### 4.4 檔案清單（估算 8 檔 —— 所以要行呢個 gate）

| # | 檔案 | 動作 |
|---|---|---|
| 1 | `data/history-sources.ts` | 新增：型別 + 內容 |
| 2 | `app/source-lab/page.tsx` | 新增：索引頁 |
| 3 | `app/source-lab/[id]/page.tsx` | 新增：條目頁（`params` 係 Promise，要 `await`）|

第 7、8 項係 **Integration Requirement**（CLAUDE.md §4）—— 冇呢兩項就係一個學生搵唔到嘅孤兒功能，唔算完成。

## 5. 建議的第一批內容

如果 greenlight，建議先做 **3 條**跑通全條管線，唔一次過鋪 40 條：

1. **柏林封鎖（1948-49）** — `cold_war`。美／蘇／英三方敘事對立，一手文件充足，考評局熱門。
